# secret-scan allowlist（scripts/secret-scan-allowlist.txt）— atlas-go 副本
# SSOT: a2a-dev scripts/secret-scan-allowlist.txt（格式說明同上游）
#
# 用途：對「確實不是機密、但形狀像機密」的東西做**逐條、可審計**的豁免。
# 格式：<path-glob>  [pattern-name …]  # 理由
#   - 只寫 glob  → 豁免該檔的**所有**樣式
#   - 再寫樣式名 → 只豁免列出的樣式（未列出的仍會被擋）
#   - `#` 之後是理由（必填；reviewer 靠它判斷豁免是否還成立）
# 可用樣式名：telegram_bot_token / openai_sk_key / github_token / aws_access_key_id /
#            private_key_block / slack_token / google_api_key
#
# 三種機制怎麼選（避免把 allowlist 當萬用橡皮擦）：
#   ① 文件裡的**範例**（*.md、docs/**、*.example、*sample*、*template*）→ **預設就是 warn-only**，
#      不必寫在這裡；只有 `--strict` 才會失敗。
#   ② 單行特例（測試 fixture、示範字串）→ 在該行尾加 `# secret-scan-allow: <理由>`，不必改本檔。
#   ③ 整個檔案性質上必須保留該字串（例如掃描器自己的樣式表/測試資料）→ 才寫進本檔。
#
# ⚠️ 「無效的舊 token」也要豁免嗎？ → **不要**。死 token 留在 repo 仍是外洩面（bot 可被重新註冊）
#    且會誤導（plist/.env 還在用它）。正確做法是**移除 + 換掉使用端**，不是加豁免。
