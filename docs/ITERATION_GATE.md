# ITERATION GATE v1.0
## 用途
每次 AI 完成一輪實作後，必須執行本閘門的自我檢查。所有閘門**全部通過**才能宣告本輪迭代完成。任一閘門不通過 → 回退，分析原因，重新開始。
---
## Gate 1: 數學深度
### 檢查項目
- [ ] 1.1 核心計算包含至少一處**矩陣運算**或**非線性優化**
  - 矩陣運算範例：`w'Σw`、矩陣乘法、共變異數矩陣估計、特徵值分解
  - 非線性優化範例：quadratic programming、gradient descent、Newton's method
  - **若核心計算全部是純量線性組合（`a*w1 + b*w2 + c*w3`），此項失敗**
- [ ] 1.2 輸出來自**真實資料的計算**，無硬編碼假資料
  - 反例：`return []Result{{0.05, 0.10}, {0.08, 0.12}}`（硬編碼）
  - 反例：`MaxDrawdown: 0 // single day`（逃避計算）
  - 正例：從歷史資料計算出的數值
- [ ] 1.3 無「佔位符」或「TODO: implement later」
  - 所有程式碼路徑都是完整實作
  - 不接受 `return 0 // placeholder`
### 判定
若 1.1 AND 1.2 AND 1.3 全部通過 → Gate 1 通過
若任一失敗 → Gate 1 失敗
### 失敗時的診斷問題
Q: 核心計算的本質是什麼？
Q: 為什麼不能用矩陣或非線性形式表達？
Q: 是否選錯了任務範圍？（太簡單，沒有深度提升空間）
---
## Gate 2: 資產通用性
### 檢查項目
- [ ] 2.1 模組在**資產類別改變時行為自動適應**
  - 測試方式：輸入「台股股票」→ 再輸入「黃金 ETF」→ 兩次輸出的計算路徑不同
  - 反例：對黃金 ETF 一樣呼叫 P/E 計算（黃金沒有 earnings）
  - 正例：對股票用 Value/Quality 因子，對黃金用 PreciousMetals 因子
- [ ] 2.2 無隱含的資產類別假設
  - 反例：假設所有 symbol 都有 P/E 和 P/B 數據
  - 反例：假設所有 symbol 的價格單位是新台幣
  - 正例：對無法取得資料的資產類別，明確標記 fallback 並退回 0
- [ ] 2.3 至少有一個跨資產類別的測試案例
  - 測試組合包含 2 種以上資產類別（如股票 + 黃金 ETF + 白銀 ETF）
  - 每種資產類別的行為不同且合理
### 判定
若 2.1 AND 2.2 AND 2.3 全部通過 → Gate 2 通過
若任一失敗 → Gate 2 失敗
### 失敗時的診斷問題
Q: 模組中哪一行假設了「所有 symbol 都是股票」？
Q: 黃金 ETF (00635U) 和台積電 (2330) 在這個模組中是否被同等對待？
Q: 如果不是——它們的差異體現在哪裡？
---
## Gate 3: Falsifiability
### 檢查項目
- [ ] 3.1 存在至少一個**邊界案例測試**（edge case）
  - 範例：N=2（極少資產）、VIX=0（無波動）、資料不足 20 天
  - 測試必須可執行（`go test` 可跑）
  - 測試必須有 assert（不能只 print 結果）
- [ ] 3.2 存在至少一個**極端案例測試**（stress case）
  - 範例：2020/03 高波動期、2022/06 升息期
  - 測試必須檢查模型在極端條件下是否合理
  - 不接受「所有測試都是 happy path（正常市場）」
- [ ] 3.3 存在一個**可被 falsify 的斷言**
  - 斷言形式：「在條件 X 下，模型輸出應滿足 Y」
  - Y 必須是可量化的（數字），不是主觀的（「合理」、「正確」）
  - 反例：「權重應該合理」——什麼叫合理？
  - 正例：「權重總和應 = 1.0，誤差 < 0.001」
### 判定
若 3.1 AND 3.2 AND 3.3 全部通過 → Gate 3 通過
若任一失敗 → Gate 3 失敗
### 失敗時的診斷問題
Q: 有沒有一個測試案例，你「希望」它失敗？
   （如果沒有——你的測試只是在確認 happy path）
Q: 極端市場條件下（VIX=80, 2020/03），模型的行為是什麼？
   這合理嗎？
Q: 你能否用一句話描述「什麼情況下這個模型是錯的」？
---
## Gate 4: 程式碼預算
### 檢查項目
- [ ] 4.1 新增行數 ≤ 上限
  - P0-1 (optimizer 重構)：≤ 500 行
  - P0-2 (貴金屬因子)：≤ 300 行
  - P1 (壓力測試升級)：≤ 200 行
- [ ] 4.2 新增檔案數 ≤ 上限
  - P0-1：0（修改現有，不新建）
  - P0-2：0（修改現有，不新建）
  - P1：0（修改現有，不新建）
- [ ] 4.3 新增外部依賴 ≤ 上限
  - P0-1：≤ 1（gonum 或自建）
  - P0-2：0（純 Go 標準庫）
  - P1：0（純 Go 標準庫）
- [ ] 4.4 無重複程式碼（DRY 違規）
  - 無複製貼上的邏輯區塊
  - 黃金和白銀的因子計算共用程式碼，不是各寫一份
### 判定
若 4.1 AND 4.2 AND 4.3 AND 4.4 全部通過 → Gate 4 通過
若任一失敗 → Gate 4 失敗
### 失敗時的診斷問題
Q: 超過預算的是新功能還是重複程式碼？
Q: 能否透過刪除舊的無用程式碼來騰出空間？
Q: 任務範圍是否過大？（考慮只做最小可行版本）
---
## Gate 5: 回歸測試
### 檢查項目
- [ ] 5.1 `go build ./...` 通過
- [ ] 5.2 `go test ./internal/portfolio/...`（或對應模組）全部通過
- [ ] 5.3 `go vet ./internal/portfolio/...` 無錯誤
- [ ] 5.4 現有測試無 broken（未改變外部行為）
- [ ] 5.5 無 `// TODO` 或 `// FIXME` 遺留（除非標註為「v2 功能」且有明確理由）
### 判定
若 5.1 AND 5.2 AND 5.3 AND 5.4 AND 5.5 全部通過 → Gate 5 通過
若任一失敗 → Gate 5 失敗，修復後重新檢查
---
## 最終判定
Gate 1 (數學深度):    通過 / 失敗
Gate 2 (資產通用性):  通過 / 失敗
Gate 3 (Falsifiability): 通過 / 失敗
Gate 4 (程式碼預算):  通過 / 失敗
Gate 5 (回歸測試):    通過 / 失敗
若 5 個 Gate 全部通過 → ✅ 本輪迭代完成，可以提交
若任一 Gate 失敗     → ❌ 本輪迭代失敗，回退，分析原因，重新開始
---
## 回退策略
### 連續 1 輪失敗
1. 確認失敗的 Gate
2. 分析根本原因（是設計問題還是實作問題？）
3. 修正後重新執行所有 Gate
### 連續 2 輪失敗
1. **停止所有程式碼修改**
2. 輸出以下診斷報告：
迭代卡關診斷
失敗的 Gate：列出
卡住的具體問題：一行描述
已嘗試的方法：
1. 方法 A — 為何失敗
2. 方法 B — 為何失敗
根本原因分析：是數學問題還是實作問題？
建議的解決方向：縮小範圍 / 改變方法 / 尋求外部參考
3. **不要繼續硬寫程式碼**
### 連續 3 輪失敗
1. 輸出完整診斷報告
2. 將任務標記為 `BLOCKED`
3. 建議任務拆分：將當前任務拆成 2-3 個更小的子任務，每個子任務仍有獨立的深度閘門
---
## 輸出模板
AI 在完成一輪實作後，必須使用以下模板輸出：
Iteration Gate Report — Round N
Gate 1: 數學深度
- 1.1 非線性/矩陣運算：是/否 — 具體位置
- 1.2 無硬編碼假資料：是/否
- 1.3 無 TODO 佔位符：是/否
- 判定：通過/失敗
Gate 2: 資產通用性
- 2.1 資產類別自動適應：是/否 — 如何適應
- 2.2 無隱含資產假設：是/否
- 2.3 跨資產測試案例：是/否 — 測試名稱
- 判定：通過/失敗
Gate 3: Falsifiability
- 3.1 邊界案例測試：是/否 — 測試名稱
- 3.2 極端案例測試：是/否 — 測試名稱
- 3.3 可量化斷言：是/否 — 斷言內容
- 判定：通過/失敗
Gate 4: 程式碼預算
- 新增行數：N / 上限
- 新增檔案：N / 上限
- 新依賴：N / 上限
- DRY 檢查：通過/失敗
- 判定：通過/失敗
Gate 5: 回歸測試
- go build: 通過/失敗
- go test: 通過/失敗
- go vet: 通過/失敗
- 判定：通過/失敗
最終判定
- 通過 Gate 數：N / 5
- 結果：✅ 提交 / ❌ 回退
- 若失敗，失敗原因：一句話

## 補充規則
### 禁止的閘門作弊行為
以下行為視為閘門作弊，直接判定**全部 Gate 失敗**：
| 作弊行為 | 例子 |
|----------|------|
| 寫一個假測試來通過 Gate 3 | `assert.Equal(t, 1.0, 1.0)` 這種恆真測試 |
| 把深度邏輯包裝成外部依賴來繞過 Gate 4 | 「引入一個第三方 portfolio optimizer 庫」而不自己實作 |
| 用註解來滿足 Gate 1 | `// TODO: 改成矩陣運算` — 不算通過 |
| 刪除舊測試來通過 Gate 5 | 測試失敗 → 直接刪掉測試 |
### 例外申請
若某個 Gate 的規則在此任務中確實不適用，可以申請例外：
例外申請格式：
Gate: 編號
原因: 為何此規則在此任務中不適用
替代方案: 用什麼機制來確保品質
例外必須在開始實作前申請，不能在失敗後補申請。
