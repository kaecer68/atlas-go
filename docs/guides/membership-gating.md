# 會員內容鎖住三原則（Membership Gating）

> **版本**: v1.0
> **狀態**: 正式（2026-08-19 業主定案）
> **適用**: 所有「內容鎖住 / 會員制 gating / premium 即時值」的前端與產品設計
> **關聯實作**: `shared_web/static/js/page-shells/methodology.js`（第二層公開數據開放即本原則落地）

---

## 緣起

methodology 第二層（台灣出口與半導體景氣）原先把三個指標一併標為「資料源未接入」，其中
`export_electronics`（電子出口）與 `tsmc_revenue`（台積電月營收）其實有**公開 API**
`/api/macro/snapshot/latest`（GET、無 tier gate、人人可抓）供電；只有 `semi_imp`
（半導體設備進口）真無資料源。把「公開數據」也鎖住，會讓用戶判定這是「問題系統／不靠譜」。
因此業主定案以下三原則，作為所有 gating 決策的最高準則。

---

## 三原則（2026-08-19 業主定案）

### 原則A — 非公開數據：只有「非公開數據」才鎖

> 只有**資料本身非公開發布**的內容才需要鎖住。

- 判定基準：數據來源是否為「任何會員／任何人都能直接取得的公開資料」。
- 來源是公開 API、公開網站、公開統計（如 `/api/macro/snapshot/latest` 的電子出口、台積電月營收）→
  **一律開放展示**，不 gate。
- 反例：我們從未公開發布、也無法被一般用戶自行取得的內部分析結果（如特定的獨家模型輸出）。

### 原則B — 獨家算出：我們自己算出來／獨家的數據才鎖

> 只有「我們自己算出來、或具有獨家性、別人不容易拿到」的數據才鎖住。

- 重點在「是否容易被取得」：
  - 容易被取得（公開數值、公開統計、可免費抓的 API）→ 開放。
  - 需要付費訂閱、或需要我們內部計算／組合才有、別人拿不到的 → 才考慮鎖。
- 即使數值「經過我們整理」，若原始資料本身公開且易取得，傾向開放；鎖的門檻是「獨家性 + 取得成本」。

### 原則C — 完整板塊：鎖住時應集中在「獨立且完整的功能板塊」

> 若要鎖住數值，應把「被鎖的內容」集中在**獨立且完整的功能板塊**（整塊 premium），
> **不允許在單一功能卡片內「有的有值、有的沒有」**（會讓用戶判定為「問題系統／不靠譜」）。

- **板塊化鎖**：該鎖的資料全部集中在同一個「整塊 premium」的板塊，用戶一眼看懂那是付費內容。
- **禁止卡片內混雜**：同一張功能卡片／同一模組內，不允許「這個指標有值、那個指標被鎖／未接入」。
- **社群／公開數據一律開放展示**：只要是社群或公開數據，就不該出現在被鎖的卡片裡造成混亂。

---

## 決策流程（遇到「要不要鎖」時的 check）

1. 資料是否**公開發布 / 人人可抓**？是 → **開放**（原則A）。
2. 是否為**我們獨家算出／別人拿不到**？否 → **開放**（原則B）。
3. 確定要鎖 → 確認鎖的內容**都在同一個完整 premium 板塊**，且
   **同一卡片不混雜「有值／沒值」**（原則C）。
4. 社群／公開數據 → 一律開放展示。

> 三原則採「任一開放條件成立即開放」的邏輯：只要滿足 A 或 B 的「開放」方向，就應開放；
> C 是「要鎖時」的結構性約束。
