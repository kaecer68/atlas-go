# P0.2 Root Cause Analysis — Data Governance Issues

**Date**: 2026-06-02  
**Branch**: `feat/data-organization-governance`  
**Methodology**: Git archaeology (commit traces), code reference analysis, filesystem forensics  
**Scope**: All 14 confirmed issues from P0.1 verification audit + 1 correction note on A.4

---

## Executive Summary

All 14 confirmed data governance issues trace to **3 fundamental gaps**, none of which are individual developer errors — they are systemic architecture-level omissions that compounded over 64 days of development (2026-03-30 → 2026-06-02).

### The 3-Root-Cause Tree

```
All 14 Issues
    │
    ├── FG-1: No Data Governance Convention Exists (affects 10 issues)
    │   └── No standard for storage, naming, organization, or documentation of data assets
    │
    ├── FG-2: Data Directory Gitignored from Day 1 (affects 9 issues)
    │   └── /data/state/ excluded from git since commit #2 on 2026-03-30
    │   └── Made all enforcement structurally impossible
    │
    └── FG-3: Documentation Created Once, Never Maintained (affects 5 issues)
        └── DATA_ARCHITECTURE.md created 2026-05-29 covering 5 of 39 data types (13%)
        └── No mechanism to keep docs in sync with code growth
```

### Why This Happened

The root cause is not developer negligence — it is **the absence of institutional mechanisms**:

1. **No one could see data changes** — `/data/state/` was gitignored from day 1, so no PR reviewer ever saw data file additions
2. **No standard existed to follow** — no document specified how to name, organize, or document data files
3. **No enforcement existed to fail** — no CI check, pre-commit hook, or PR gate ever validated data governance

The system has 1,144 commits, 190 graphify communities, robust CI for Go code quality, and zero infrastructure for data governance.

## Fundamental Gap 2: Data Directory Gitignored from Day 1

**Evidence**: The second commit in repository history (`f71c0a2`, 2026-03-30) added `/data/state/` to `.gitignore`:

```
commit f71c0a2de021371beacb9c76a374aef1d47a222b
Author: Kaecer Boss <kaecer@gmail.com>
Date:   Mon Mar 30 08:22:48 2026 +0800
    Remove generated artifacts from repository

+ /data/state/
+ /data/replay/*.jsonl
```

This decision classified ALL data files as "generated artifacts" — equivalent to build outputs. The gitignore entry has never been modified or removed since.

**Structural consequences of FG-2**:
- 🔴 No git diff for any data file change → PR reviewers never see data additions
- 🔴 No git blame on data files → no accountability for who added what or why
- 🔴 No CI checks possible on data file conventions → automated enforcement impossible
- 🔴 No capacity to track data type additions over time → documentation decay invisible
- 🔴 Graphify excludes `data/` via `.graphifyignore` → knowledge graph sees Go code only

**Issues caused by FG-2**: A.2 (flat structure), A.3/C.2 (naming — no git history to trace), A.4 (orphaned files — invisible to cleanup), A.6 (mixed naming — no diff review), B.3 (catalog — no add triggers), C.1 (schema — no enforcement), C.4 (graphify — data excluded), C.5 (discovery — invisible), C.6 (discoverability — no searchable history)

## Fundamental Gap 3: Documentation Created Once, Never Maintained

**Evidence**:

- `docs/DATA_ARCHITECTURE.md` — created **2026-05-29** (commit `5557589`, just **4 days** before this audit), covers 5 data types: sessions, recommendation_outcomes, PostgreSQL tables, darwinian_weights, darwinian_history
- `docs/data_sources.md` — created **2026-05-07** (commit `8a468c6`), last updated 2026-05-29 (commit `9d8df30`), covers external API providers only, zero sections on internal data storage
- Neither document has ever been updated to reflect new data types added after creation

**Coverage gap**:
- DATA_ARCHITECTURE.md: 5 of 39 data types documented = **12.8% coverage**
- When created (2026-05-29): ~15 data types already existed; it documented 5 = **33% coverage at creation time**, already incomplete
- 24 flat files + subdirectories have NO mention in any documentation
- Zero documentation for: margin, capital_flow, macro, export, alerts, geopolitical, ml_models, swarm_training, eventlogic, traces, windows, autobacktest, and all kebab-case dirs

**No mechanism exists to maintain documentation**:
- No CI check requires doc updates on new `data/state/` code references
- No PR template asks "does this change require data documentation updates?"
- No `check_data_catalog.sh` or similar script exists in `scripts/ci/`

**Issues caused by FG-3**: B.1 (DATA_ARCHITECTURE.md incomplete), B.2 (data_sources.md scope), B.3 (catalog), C.5 (discovery), C.6 (AI queries)
