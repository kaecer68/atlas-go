## 1. 一句話定位

atlas-go 是給**台灣散戶**的**模擬交易暨投資策略觀測輔助智慧平台**：從台灣市場的獨特屬性出發，觀測法人資金的客觀數值變化，預測「錢潮」流向，用機器自動化與白話解釋，幫散戶建立可紀律執行的投資判斷流程。

## 2. 目標用戶

- **核心層：會正確使用 AI 的散戶**。他們會用 Hermes Agent / OpenClaw 等 AI agent 透過 atlas-mcp 追问、驗證、補充網頁上看不懂的內容。平台的語意層（白話解釋 + agent 補充解說）主要為這層設計。
- **外圈層：一般散戶**。只使用網頁介面；依賴直觀提示、白話文案與預設呈現。
- **非用戶**：法人/機構操盤手。機構專用的數學演算工程（複雜衍生品定價、高頻執行演算法等）**不是**本專案重點，不為此投入。

## 3. 產品邊界

**做**：
- 模擬交易（simulation-first，含 AI 模擬投組與策略實驗）
- 投資策略**觀測**：資金勢力、錢潮預測、產業輪動、策略競爭、風險提示
- 白話解釋與 agent 補充解說（數值 → 語意）
- 台灣市場特有的週期與事件（春節、選舉、除權息、月底作帳、MSCI/ETF 調整）

**不做**：
- 實盤下單系統（live broker 路徑僅為研究保留，需雙重 opt-in，非產品主線）
- 機構級定量工程（見 §2 非用戶）
- 投資建議的保證（見 §9 誠實聲明）

## 4. 設計原則：機器自動優先

優先級：**機器自動執行 > 人機協同**。三個一等機制：

1. **自動排程**：資料抓取、回測、校準、實驗、報告、清理全部由背景任務驅動；人工觸發是例外。
2. **自動糾錯**：熔斷、降級（fallback/stale cache）、自動回滾（AutoRollback）、缺口自動補抓；任何「只告警不修復」的機制都應被檢討。
3. **自動進化**：回測 → 達爾文權重 → 實驗候選 → 評審 → 晉升/回滾的閉環無需人工閘門；人工 override（pause/ban/promote）保留但需 API key 並入審計。

人機協同的介面位階：**網頁介面優先**（散戶的主入口），**atlas-mcp 為輔**（Agent Support：當網頁難以說明清楚的內容，由 Hermes Agent / OpenClaw 透過 MCP 補充解釋）。文件、入門引導、功能曝光的順序都應反映這個位階。

## 5. 台灣市場前提假設（設計輸入，非僅評估框架）

以下六項是系統設計的**前提假設**，所有資金流模型、事件模型與 UI 敘事都應與其一致：

1. **外資主導**：外資持有台股市值約四成、持有台積電逾七成；淺碟市場下外資進出對指數影響放大。
2. **美元依賴**：台灣無內銷市場縱深，絕對外貿依賴；匯率政策緊盯美元，USD/TWD 是核心變數。
3. **美股連動**：前一交易日美股（尤其 SOX、NVDA、TSM ADR）是台股開盤方向的主要訊號。
4. **電子偏科**：電子股佔市值約 70-75%，台積電單一公司佔 38-43%，半導體週期主導大盤。
5. **外資導火索**：外部因子（美元利率、美債殖利率、日圓、原油、VIX）透過外資行為傳導至台股，是錢潮的上游。
6. **週期慣性**：春節紅包行情（近 20 年開紅盤日上漲機率 71-75%）、選舉行情（地方選舉證據較強、總統大選不一致，需分層對待）、除權息旺季、月底/季底作帳等，形成可驗證的統計慣性。

> 數據出處見審計報告 §5.2。所有前提都應持續用資料驗證，而非當作永恆真理（見 §8 校準哲學）。

## 6. 方法論主軸：錢潮因果鏈

系統的核心因果鏈（各環節的實作現況與修復計畫見 fix manifest）：

```
外部因子（美元利率/美債/日圓/原油/美股）
  → 推估外資動向（現貨 T86 + 期貨未平倉，領先→落後排列）
  → 推估其他資金勢力（投信/自營/官股/散戶）的可能動態
  → 觀測・預測・修正錢潮流向（預測 vs 實際必須閉環）
  → 結合產業、週期、供應鏈連動 → 產業與個股標的
  → 漲跌趨勢預測 + 策略競爭比較
  → 散戶可理解的呈現（網頁）+ agent 補充解說（MCP）
```

**預測可信的三要件**（任何預測功能的最低門檻）：領先指標資料、預測 vs 實際的同單位誤差追蹤、誤差回饋校準。缺任一者，對外呈現必須標示「校準中」而非假裝精準。

## 7. 資金勢力分類學（⚠️ 待業主簽核）

**分類語意權威**：本節僅摘錄散戶/產品語意；**唯一正本在 `docs/specs/capital-flow-seven-dimension-spec.md` §4 D-CF-04**，所有活體文件、UI、MCP 描述、active docs 必須與其一致。

### 7.1 七維錢潮雷達（3+2+2 分層）— 散戶介面摘要

七維錢潮雷達：三大法人資金流、兩類行為代理、兩項領先／跨市場訊號；各維度角色與資料品質不同。

- **官方法人（3）** — 三大法人：外資 / 投信 / 自營商（T86 第一方資料）。共振模型只看這層；對應 dimension_role = `official_actor`。
- **行為代理（2）** — 官股 / 散戶（非 T86 第一方、目前用代理方法）。缺資料不補 0；對應 dimension_role = `behavioral_proxy`。
- **領先／跨市場訊號（2）** — 外資期貨未平倉 / TSM ADR（跨單位 / 跨市場訊號，**不**視為台股資金主體）。對應 dimension_role = `positioning_indicator` / `cross_market_signal`；UI 合併為同一 tier。

> 「7-Force」與「七大資金勢力」僅作為向後相容別名使用（spec §4 D-CF-05）；UI 必須同時顯示三層角色，**不得讓使用者誤認七個同級法人**。

### 7.2 歷史紀錄（deprecated 看待，七同級語意已棄）

**舊版問題（已修正，保留供 audit 對照）**：manifest E05 前曾將七維混雜為「七大資金勢力」，期貨與 TSM ADR 拿 30% 權重、外資 0%（活體觀測 §七）。問題核心：股數、期貨口數、百分比不可同分母（CF-INV-07）。

### 7.3 完整語意、證據、計算與可變更程序

詳見 `docs/specs/capital-flow-seven-dimension-spec.md` §4 D-CF-04 / §6 / §7 / §15。**本節不再單獨維護內容**；任何修改必須從 canonical spec 同步過來。

## 8. 校準哲學：heuristic 一律經過驗證管道

任何外部經驗法則（如「外資連買 5 天是信號」「分點集中度 >50%」「期貨淨多 >20,000 口」）**不得直接硬編碼為規則**，必須經過：

```
假設登錄 → 歷史資料校準（命中率/報酬統計）→ 寫回 parameters.json → 持續追蹤命中率 → 退化自動降權
```

這是本系統對其他平台（規則寫死）的核心差異化，也是「自動進化」的具體實踐。

## 9. 誠實聲明（對外文案必須遵守）

- 法人資料 T+0 盤後才公布，使用者最早 T+1 才能行動；平台不提供「即時跟單」幻想。
- 「安全窗口」「連買慣性」都是**機率性**陳述，呈現時必須附歷史命中率，不得寫成確定承諾。
- 平台的價值主張是：把「觀測 → 解讀 → 追蹤 → 紀律」系統化，降低散戶的資訊處理成本與情緒干擾。**不使用「找到市場漏洞」類行銷語言。**
