# Atlas 深度開發憲法 v1.0
## 共 8 條文
## 第零條：本憲法的目的
本憲法存在的原因：AI Coding 在既有程式碼池中會陷入「讀取現有 pattern → 產生更多相同 pattern」的淺層循環。本憲法透過強制性規則打斷這個循環。
**所有規則的優先級高於 AI 的預設行為。違反任一條 = 任務失敗。**
---
## 第一條：深度定義
在本工作區中，「深度」的操作性定義是：
> 一個模組是「深的」，若且唯若：
> 1. 其核心計算**包含矩陣運算或非線性優化**，而非純量線性組合
> 2. 其輸出來自**真實資料的計算**，而非硬編碼常數或假資料
> 3. 其行為在**資產類別改變時仍然正確**（股票→黃金→ETF，模型自動適應）
**淺層範例（禁止產出）**：
- `score = 0.3*a + 0.25*b + 0.2*c`（純線性加權，無矩陣）
- `return []Result{{0.05, 0.10}, {0.08, 0.12}}`（硬編碼假資料）
- `MaxDrawdown: 0 // single day`（逃避真實計算）
**深層範例（期望產出）**：
- 從 60 天歷史報酬計算共變異數矩陣，使用 Ledoit-Wolf shrinkage
- 透過 quadratic programming 求解 min w'Σw
- 多日壓力測試產出真實的最大回撤路徑
---
## 第二條：第一性原理優先（最高優先級規則）
**在任何程式碼讀取或撰寫之前，必須先完成以下四個步驟：**
### 步驟 1：數學模型（純方程式，禁止 pseudocode）
用標準數學符號寫下：
- 輸入變數及其定義域
- 輸出變數及其值域
- 核心方程式（使用 LaTeX 風格符號）
✅ 正確範例：
   給定 N 個資產的日報酬序列 rᵢ(t)，i=1..N, t=1..T
   共變異數矩陣 Σ_{ij} = (1/T) Σₜ (rᵢ(t)-μᵢ)(rⱼ(t)-μⱼ)
   最小變異數組合：minimize w'Σw
                     subject to Σwᵢ = 1, 0 ≤ wᵢ ≤ w_max
❌ 錯誤範例：
   演算法：
1. 計算每個股票的得分
2. 根據得分分配權重
3. 檢查上限
### 步驟 2：Falsification 條件
定義三個具體情境，若模型在這些情境下失敗，則模型是錯的：
情境 A（邊界案例）：組合僅有 2 個資產時，模型是否合理？
情境 B（極端案例）：2020/03 高波動期，模型是否比等權組合好？
情境 C（正確性檢查）：權重加總是否等於 1？
### 步驟 3：資料依賴宣告
列出所有需要的輸入資料、其來源、計算方式：
資料	來源	計算方式
日報酬序列	HistoricalPrices.GetReturns()	(Pₜ - Pₜ₋₁) / Pₜ₋₁
無風險利率	台灣 10 年期公債殖利率	外部 API
### 步驟 4：參數宣告（含溯源）
參數	值	來源
回顧天數	60	學術文獻建議 60-120 天
w_max	0.15	現有 constraints.MaxPositionPct
**禁止行為**：
- ❌ 「我先看一下 optimizer.go 是怎麼寫的」（這是淺層循環的起點）
- ❌ 跳過數學模型直接寫 pseudocode
- ❌ 憑空出現的常數無來源說明

## 第三條：程式碼預算制
任何任務的程式碼產出有硬性上限。**超過預算 = 任務失敗，必須簡化或拆分。**
| 任務類型 | 最大新增行數 | 最大新增檔案數 | 最大新依賴數 |
|----------|-------------|---------------|-------------|
| 核心重構（修改既有檔案的核心邏輯） | 500 | 0（修改現有，不新建） | 1 |
| 新因子模組（擴展現有 FactorEngine） | 300 | 0（修改現有，不新建） | 0 |
| 測試/驗證 | 200 | 1 | 0 |
**核心原則**：深度來自**重構既有模組**，不是**新增更多檔案**。
**禁止行為**：
- ❌ 「我新建一個 covariance_optimizer.go 來放新邏輯」（應該改 optimizer.go）
- ❌ 「我新建一個 gold_factor.go 專門處理黃金」（應該擴展 factor_engine.go）
- ❌ 「我新建一個 utils/math.go 放輔助函數」（輔助函數放在使用它的檔案裡）
---
## 第四條：修改邊界規則
修改 Atlas 既有程式碼時，必須遵守以下邊界：
**可以做的事**：
- ✅ 修改任何 `.go` 檔案的內部實作邏輯
- ✅ 新增私有方法或輔助函數
- ✅ 在既有 struct 中新增欄位
- ✅ 替換硬編碼假資料為真實計算
**不可做的事**：
- ❌ 改變任何公開方法的簽章（參數類型、回傳類型）
- ❌ 刪除任何公開方法
- ❌ 改變 `internal/domain/` 中的任何型別定義
- ❌ 改變 JSON tag 或序列化格式
**特別豁免**：`GetEfficientFrontier()` 目前回傳硬編碼假資料。此方法的**回傳結構**不變（仍是 `[]struct{ Return, Risk float64 }`），但**計算邏輯**必須完全重寫。

## 第五條：迭代深度閘門
**每次 AI 完成一輪實作後，必須自我檢查以下三個問題。任一回答為「否」→ 本輪變更拒絕合併。**
### Gate 1: 數學深度
> 這個模組的核心計算是否從「純量線性組合」進化為「矩陣運算或非線性優化」？
- 若核心計算仍為 `a*w1 + b*w2 + c*w3` 形式 → **不通過**
- 若核心計算包含矩陣乘法（w'Σw）、quadratic programming、或非線性函數 → **通過**
### Gate 2: 資產通用性
> 當輸入從「純台股」切換為「台股 + 黃金 ETF + 白銀 ETF」時，模型行為是否自動適應？
- 若模型對黃金 ETF 呼叫 P/E 因子（黃金沒有 earnings）→ **不通過**
- 若模型根據資產類別分派不同因子 → **通過**
### Gate 3: Falsifiability
> 是否存在一個可執行的測試，能證明「模型在特定情境下是錯的」？
- 若所有測試都是 happy path（正常市場、多資產、充足資料）→ **不通過**
- 若存在 edge case test（N=2、高波動期、資料缺失）→ **通過**

## 第六條：溝通規範
### AI 在開始任何工作前，必須先輸出：
📐 數學模型：方程式
🧪 Falsification：三個情境
📊 資料依賴：表格
📏 程式碼預算：預計行數 / 上限
### AI 在完成一輪工作後，必須先輸出：
🔍 Gate 1 (數學深度): 通過/不通過 — 原因
🔍 Gate 2 (資產通用性): 通過/不通過 — 原因
🔍 Gate 3 (Falsifiability): 通過/不通過 — 原因
📏 程式碼預算: 實際行數 / 上限
若全部通過 → 可以合併
若任一不通過 → 回退，分析失敗原因，重新開始
### 禁止的語言模式
以下語句在本工作區中代表「AI 正在逃避深度思考」：
| 禁止語句 | 為什麼是逃避 |
|----------|------------|
| 「我們可以之後再優化」 | 深度不能推遲——這就是唯一要做的事 |
| 「這是一個簡化版本」 | 簡化 = 淺，必須從開始就做對 |
| 「先跑起來再說」 | 淺層程式碼跑起來也沒意義 |
| 「加一個配置參數讓用戶自己調」 | 把數學問題外包給使用者 |
| 「我先看一下現有程式碼」 | 第一性原理優先——先想數學，再看程式碼 |

## 第七條：失敗處理
### 連續 2 輪迭代無法通過深度閘門時：
1. **停止所有程式碼修改**
2. **分析卡在哪個具體的數學問題上**
3. **縮小任務範圍**（例如：先只做最小變異數，不做夏普最大化）
4. **從數學模型重新開始**（不繼續修改上一輪的程式碼）
### 如果一個任務在 3 輪迭代後仍無法通過：
- 輸出：卡住的具體數學問題、嘗試過的方法、建議的替代方案
- **不要繼續硬寫程式碼**

## 第八條：校準 Artifact 治理（2026-07-06 補遺）

### 背景

系統參數（`configs/parameters.json`）由背景校準任務（auto_calibrate 7d、factor_weight_calibrator、self_calibrate 等）定期更新，這些任務會在寫入前產生 `*.snapshot.bak` 備份。這不是 AI agent 的工作產物，而是**系統執行期的校正結果**。

### 規則

1. **`configs/parameters.json` 應定期 commit**：這是校準 SOTA 的 source of truth（歷史已 commit 13 次），不是 generated artifact。

2. **`*.snapshot.bak` 絕不 commit**：這是 SaveWithRollback 的快照備份（供 RestoreFromBackup 復原用），已在 `.gitignore` 中排除。若 `git status` 顯示，刪除即可。

3. **Agent 遇到未知修改時的處理流程**：
   - Step 1：確認來源（`git log --all --oneline -- <file>`）
   - Step 2：確認是否為背景任務產物（查 AGENTS.md 快速對照表）
   - Step 3：若為校準結果 → 提交；若為快照備份 → 忽略/刪除
   - **禁止猜測、禁止未經確認直接刪除、禁止 stash/checkout 掩蓋問題**

4. **跨 agent 一致性**：`docs/operations/version-bumping.md` 與 `AGENTS.md` §「高頻陷阱速查」互為備援，確保不同 model/tool 的 agent 都能找到正確判斷依據。
