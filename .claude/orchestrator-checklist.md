# Sisyphus 派遣前檢查清單

## 強制檢查（每次派遣前必須執行）

### 1. 重複任務檢查
- [ ] 是否有進行中的背景任務處理相同問題？
- [ ] 過去 30 分鐘內是否已完成類似任務？
- [ ] 輸入參數是否與進行中的任務 90% 相同？

**如果任一為「是」→ 不派遣新代理，改為：**
- 查詢現有任務狀態（background_output）
- 或等待現有任務完成

### 2. 工具歷史檢查
- [ ] 這個問題是否已經用 grep 搜尋過？
- [ ] 這個檔案是否已經被 read 過？
- [ ] 是否已經有足夠資訊回答問題？

**如果已執行過相同工具 → 不派遣探索代理，直接綜合現有資訊**

### 3. 任務範圍控制
- [ ] 任務描述是否具體？（不是「分析整個系統」）
- [ ] 是否指定了具體的檔案或模組？
- [ ] 是否設定了明確的完成標準？

**如果任務太模糊 → 先細化任務描述，再派遣**

## 派遣模板（必須包含）

```
## 任務：[具體描述]

## 已執行的工具（請勿重複）
- [工具]: [參數] → [結果摘要]

## 限制條件
- 最多 [N] 次工具呼叫
- 禁止重複相同工具+參數
- 3 次無進展則停止並回報

## 完成標準
- [具體的完成條件]
```

## 緊急停止條件（發現任一立即停止）

1. 代理重複相同工具呼叫 2 次以上
2. 代理 10 分鐘內無任何輸出
3. 代理輸出與之前完全相同
4. 代理開始執行不相關的工具呼叫

## 死循環預防檢查點

每派遣一個代理後，設置檢查點：
- 5 分鐘後：檢查是否有進展
- 15 分鐘後：檢查是否接近完成
- 25 分鐘後：準備強制終止（如果還未完成）
