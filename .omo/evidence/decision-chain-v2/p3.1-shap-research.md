# P3.1: SHAP/LIME Contribution Decomposition — Research Note

## Recommendation: DEFER

SHAP or LIME decomposition of factor score contributions would add marginal audit value
beyond what `FactorScoreBreakdown` already provides.

### Analysis

**What we already have:**
- `FactorScoreBreakdown` shows per-factor scores with `Weight`, `Formula`, `RawInputs`,
  and `IsFallback` — this already provides factor-level attribution.
- `ConvictionBreakdown` shows step-by-step conviction calculation with `ParamRef`,
  `ParamValue`, and `Sensitivity` markers.

**What SHAP would add:**
- Interaction effects between factors (e.g., Momentum × Liquidity)
- Instance-level explanation of why THIS stock got THIS total score

**Why defer:**
1. SHAP requires a prediction model to explain — we use a weighted sum, which is
   trivially decomposable (SHAP values = weight × score per factor).
2. The existing `FactorScoreBreakdown` already captures the per-factor contribution
   with full formula transparency.
3. For a linear model (weighted sum), SHAP decomposition is identical to the
   factor weights already shown.
4. The audit value of SHAP is negligible compared to the parameter provenance we've
   already added (ParamRef, ParamValue, Source, Sensitivity).

**If we ever implement:**
- Only worth doing if we move to non-linear ensemble models (XGBoost, NN)
- Would need a model training pipeline + explanation runtime
- Best placed in `cmd/experimental/` as a proof-of-concept

### Verdict: SKIP for now. Revisit only if we adopt non-linear ensemble scoring.
